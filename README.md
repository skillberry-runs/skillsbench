# skillsbench

Hand-authored evidence, results, and insights from optimizing SkillsBench-facing skills
with [cap-evolve](https://github.com/skillberry-ai/cap-evolve).

This repo was migrated on 2026-11-09 from the `skillsbench-history` orphan branch of
`skillberry-ai/cap-evolve`, with full commit history preserved. It is one of the
per-benchmark result repos in the [skillberry-runs](https://github.com/skillberry-runs) org.

Published (rendered) at <https://skillberry-ai.github.io/cap-evolve/skillsbench/> by
cap-evolve's `pages.yml`; `.github/workflows/notify-cap-evolve-pages.yml` triggers a
redeploy on every push to `main`.

## Why this repo exists

cap-evolve work here splits into two kinds of contribution:

1. **Contributions to cap-evolve itself** — the library: features, CI/CCC infra, core
   docs. These land on `main` via normal PRs.
2. **Contributions to SkillsBench optimization** — where cap-evolve is merely the tool
   we used. Results tables, evolved skills, insight write-ups, ideas, proposals. These
   have no natural home on `main` (that tree is the library, not a lab notebook) and
   don't belong on `benchmark-history` either — that branch is machine-written
   (regenerated by `ci/benchmarks/lib/record.py aggregate`) and periodically pruned by
   `.github/workflows/benchmark-history-prune.yml`. Hand-authored content placed there
   would eventually be deleted.

This repo is the home for kind 2. Dashboard **metrics** (the numbers behind
the live results table) still go through cap-evolve's `benchmark-history` pipeline — see
`ci/benchmarks/PUBLISHING.md` in cap-evolve — since `skillsbench` is already a first-class `bench`
value there. This repo is for everything a metrics record can't hold: the narrative,
the code that got evolved, the reasoning.

## Layout

- `results/` — result tables and ledgers, one subdir per sweep/experiment.
  `results/results.json` is the canonical results ledger.
- `recipes/` — cap-evolve project configs (`capevolve.*.yaml` + `split_ids.*.json`),
  organized per experiment configuration, so a given experiment can be rerun (e.g. with a
  different model or more iterations) without needing the source worktree.
- `artifacts/` — the `seed`/`best` skill-package snapshots those recipes actually
  produced, mirroring `recipes/`'s subdirectory structure.
- `insights/` — write-ups: investigations, comparisons, reports.
- `evidence/` — concrete proof bundles for specific claims (e.g. "cap-evolve evolves
  real code, not just prose"), each with its own README, the actual before/after
  artifacts, and diffs.
- `handoffs/` — session-to-session handoff docs for in-progress experiment lines.
- `proposals/` — design docs for experiments not yet (fully) run.
- `docs/specs/` — study-level experiment design/record docs (e.g.
  `experiments_plan_v1.md`, `3x2_toy_experiment_plan.md`) — the design predates and outlives
  any single run, unlike `proposals/`'s not-yet-run scope.
- `ui/` — standalone browsable HTML artifacts (charts, heatmaps). Open directly in a
  browser from a checkout — no build step, no server.

## Working in this repo

Clone it like any repo — no worktree needed:

```bash
git clone git@github.com:skillberry-runs/skillsbench.git
```

(History note: before this migration the content lived on a cap-evolve branch that was
renamed twice on 2026-09-02: `skillbench_history` → `skillbench-history` →
`skillsbench-history`.)

Note that `intake_skillbench_c*` worktree directories and `third_party/skillbench/` paths
appearing throughout this repo are **not** typos to fix — they name real directories in
cap-evolve worktrees, and correcting the spelling would point them at paths that don't exist.

Before every commit, run `git status` and review it — double-check no `.env`, `.cache/`,
or `__pycache__/` content is staged (a `.gitignore` covers the common cases).
